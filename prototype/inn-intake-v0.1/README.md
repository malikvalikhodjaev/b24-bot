# Тестовый сценарий по ИНН — v0.1

Основа рабочего бота: v0.2.5, commit 2bc2332d2718e7270aba2089fd2e91689748effe. Это отдельная локальная форма для ручной проверки нового сценария, не серверный выпуск.

Подтверждённые требования пользователя: ИНН сначала; найти фирму и число связанных аптек; выбрать фирму целиком или аптеку из списка с FOM ID; показать ожидание загрузки; при отсутствии фирмы спросить о создании. Тот же выбор применяется к сделке и заявке.

Форма работает в браузере на http://127.0.0.1:18771. Поиск сразу обращается в Б24 только на чтение; выбора источника и учебных примеров в интерфейсе нет. Секрет подключения загружается процессом Python из прежней закрытой конфигурации на этом компьютере; в браузер, Git и журналы он не передаётся. Входные ИНН и результаты обрабатываются только в оперативной памяти процесса; повторное использование кэша ограничено 60 секундами. Сервер слушает только 127.0.0.1.

Сохранение в Б24 и Telegram-получатель обновлений отсутствуют. Финальное подтверждение завершает симуляцию; фирма, аптека, сделка, заявка, контакт и напоминание в рабочих системах не создаются. Работающий VPS-бот и основные webapp/src не меняются. Ветка: codex/inn-intake-preview.

Для запуска из корня проекта в PowerShell:

```powershell
& 'C:/Users/Lenovo/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -X utf8 prototype/inn-intake-v0.1/server.py --port 18771 --private-root 'C:/Users/Lenovo/Desktop/Datfo/datfo-crm-bot'
```

Учебные ИНН используются только автоматической проверкой: 300000101 — три аптеки (одна закрыта), 300000102 — фирма без аптек, 300000103 — две фирмы с одним ИНН, 300000199 — фирма не найдена. check_ui.cjs подставляет учебный источник в своих HTTP-запросах. Пользовательская форма всегда использует Б24; при недоступном подключении показывает ошибку, не подменяя ответы учебными.

Для связи с аптекой сервер проверяет принадлежность выбранного pharmacy_id фирме, найденной по точному ИНН. FOM ID отображается и участвует в фильтрации списка; вручную вводить его не нужно. В варианте «На фирму» pharmacy=null, company.id берётся из найденной фирмы; новая фирма имеет company.create=true после отдельного согласия и ввода названия. Для нескольких компаний по одному ИНН выбор обязателен. При ошибке чтения создание отсутствующей фирмы не предлагается как будто поиск завершился успешно.

Авторская адаптация для проверки: сохранены обсуждаемые программы, типы обращений, напоминания с шагом 30 минут, контактное лицо и вариант новой аптеки. Списки взяты из существующего публичного webapp/reference.json. Неработающая/закрытая аптека требует подтверждения сделки. Подтверждение в этой форме — только просмотр будущей привязки.

Следующий этап после ручной проверки: перенести согласованный UI и контракт target=company/pharmacy/new_pharmacy в подписанный Mini App и обработчики сделки/поддержки, сохранив роль пользователя, повторную проверку ИНН/аптеки и защиту повторного сохранения. До этого API локальной формы не является рабочим endpoint бота. Публикация и обновление VPS в этой итерации не выполняются.

Проверено: 10 тестов адаптера и контрактов, все браузерные сценарии в check_ui.cjs, ширины 320/390/1280 и тёмный режим; реальные чтения Б24 прошли. Мобильные экраны визуально проверены. Ручной отзыв пользователя ещё ожидается.


## Уточнение локальной формы — 14 октября 2026

Текущая локальная редакция продолжает сценарии рабочего v0.2.7. Название сделки и необязательный ИНН доступны сразу, без выбора способа заполнения. По ИНН определяется фирма; галочка «Оформить на конкретную аптеку (FOM ID)?» раскрывает список её аптек. После выбора точки появляется галочка «Подставить данные аптеки из Б24?»: она показывает имеющиеся бизнес-регион, город/район, адрес, текущую программу и телефон. Эти поля доступны для просмотра; данные существующей аптеки не изменяются. Введённое название сделки сохраняется при переключениях. У заявки ИНН остаётся обязательным.

В основных webapp/src также подготовлены совместимые локальные правки и повторная проверка привязки. Новая редакция ещё не опубликована на VPS; подтверждение прототипа по-прежнему ничего не записывает в Б24. Ранее описанная ветка codex/inn-intake-preview и база v0.2.5 относятся к первоначальному созданию прототипа.

Проверки: полный набор 524 теста бота, 25 тестов сценария ИНН/названия, 12 тестов адаптера прототипа; 14 сценариев основных webapp и все сценарии локальной формы на ширинах 320/390/1280. Подстановка региона/города, очистка выбранной точки и сохранение названия проверены в браузере. Экран с подставленными данными визуально проверен. Следующий этап — ручная проверка пользователем.
