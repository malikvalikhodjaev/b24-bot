# Размещение отдельного FOM-бота

Актуальный пакет v6 включает выбор русского/узбекского языка, краткую помощь по ролям, термин «заявка» для техподдержки, пользовательскую очистку, стадии техобслуживания и время решения; v1/v2/v3/v4/v5 сохранены как прежние снимки.

Подготовлен пользовательский `fom-bitrix-bot.service`; серверная установка этой редакции ещё не выполнена. SSH `BatchMode` 6 октября получил `Permission denied (publickey,password)`. Рабочий бот пока запущен на ноутбуке. Сервис дашборда и соседние проекты не требуют перезапуска.

Закрытый пакет содержит рабочую базу, регистрации и отдельную серверную `.env` с действующим подключением. Он находится в игнорируемом `data/deploy-fom-20261006`; в Git и публичные вложения пакет не помещать. Исходная локальная `.env` сохранена. Серверная копия использует прямой webhook, поскольку архивный Windows-путь на Linux недоступен.

База в подготовленном пакете — снимок этого этапа. Пока локальный бот работает, появляются новые действия. Перед фактическим переключением требуется свежая согласованная SQLite-копия после остановки локального poller; подготовленный старый снимок не должен заменять новые регистрации, заявки и историю. Серверный сервис до переноса последнего состояния не активировать.

В пользовательском PowerShell загрузить пакет и подготовительный скрипт в свой домашний каталог VPS:

```powershell
scp 'C:\Users\Lenovo\Desktop\Datfo\datfo-crm-bot\data\deploy-fom-20261006\fom-bitrix-bot-20261006-v7.tar.gz' 'C:\Users\Lenovo\Desktop\Datfo\datfo-crm-bot\deploy\prepare-fom-vps.sh' malik@130.49.168.29:/home/malik/
ssh malik@130.49.168.29 'bash /home/malik/prepare-fom-vps.sh'
```

Скрипт сохраняет существующие файлы: если каталог/юнит бота уже существуют, установка остановится для проверки. На новом пути он извлекает пакет, проверяет Python и часовой пояс, запускает тесты и онлайн-чтение, устанавливает только свой пользовательский юнит. Бот на этом шаге не запускается. При сбое проверки повторно не извлекать пакет поверх появившегося каталога; сначала изучить результат. Содержимое `.env` и базы в терминал не выводить.

Перед активацией нужно остановить единственный проверенный локальный poller с актуальным PID/командой/временем из `data/registration-process.json`. Затем в SSH:

```bash
systemctl --user enable --now fom-bitrix-bot.service
systemctl --user is-active fom-bitrix-bot.service
journalctl --user --unit fom-bitrix-bot.service --lines 20 --no-pager
```

Для работы после выхода пользователя серверный `Linger` должен быть `yes`; подготовительный скрипт только показывает его, системные настройки не меняет. Не запускать одновременно серверный и локальный poller. После активации проверить `/start`, выбор языка, рабочую карточку заявки через `/requests`, сохранённую ссылку/историю и адресную доставку двум подключённым людям.
