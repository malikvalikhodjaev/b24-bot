# Выпуск бота 0.2.0 — перенос на VPS

8 октября 2026, Asia/Tashkent. Код включает текущие формы сделки/аптеки/поддержки, контакты, типы office, поиск техников структуры Б24, распределение, стадии, напоминания, статистику и локализацию. Это первый Git-выпуск именно этого приложения; ежедневный @datfo_daily_bot — другой проект.

На этапе подготовки подтверждены SSH, пользовательский systemd с Linger=yes и отсутствие второго FOM-poller на сервере. В отдельный каталог установлен CPython 3.12.15 через uv 0.12.23 с проверкой SHA256 официального архива. Код версии 0.2.0 подготовлен к Git и серверным тестам. Установка и перенос последней базы пока не подтверждены этой записью; окончательный результат будет добавлен после переключения.

Закрытые настройки, рабочие SQLite-базы, локальные журналы и резервные копии исключены из Git. Основное руководство: [SERVER_RUNTIME.md](../deploy/SERVER_RUNTIME.md). Старые пользовательские исходники и соседние проекты не менялись.

## Проверенная подготовка сервера

Исходники опубликованы в закрытом GitHub-репозитории `malikvalikhodjaev/datfo-strategy`: ветка `codex/fom-bot-server`, коммит `6a82939c8908c6cee8205e201f208615f310d8ef`. Серверная ветка `codex/fom-bot-runtime`, коммит `16cf0e39ab15dad339ac71e483eb6c0e9b83290e`, содержит тот же каталог бота как корень. Код из Git-bundle установлен в `/home/malik/datfo-crm-bot`.

Полный набор из 472 тестов прошёл на Windows и на серверном CPython 3.12.15. Тесты формы теперь используют собственную проверенную фикстуру публикации, а тест установщика — самостоятельную фикстуру обработчиков дашборда; зависимости от закрытых локальных файлов и соседнего проекта устранены. Юнит проверен `systemd-analyze --user verify`; отдельная временная служба подтвердила Python и Asia/Tashkent с теми же параметрами PrivateTmp, NoNewPrivileges и UMask.

Рабочая служба установлена, но на этой контрольной точке **не запущена**: ActiveState=inactive, MainPID=0. Токен, подключение Б24 и базы на VPS ещё не переданы. Автоматическая проверка разрешений потребовала явного подтверждения переноса закрытых данных на этот адрес; запрос отправлен пользователю. Локальный единственный poller PID 27404 продолжает работу. Следующий шаг после подтверждения — проверка подключения только чтением, остановка этого процесса, свежий backup трёх баз, сравнение всех таблиц и включение серверной службы.
