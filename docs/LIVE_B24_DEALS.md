# Настоящие записи Б24 и управление стадиями

Локальная редакция от 4 октября 2026. Код включён в текущем `--sales-bot`, 161 тест прошёл. Живое создание в воронке 43 пока отклонено `ACCESS_DENIED`: запись не создана, проверка настоящего перехода стадии не выполнена. Это не завершённый запуск записей в данной воронке.

## Сценарий

1. Для реального теста администратор выбирает «🧪 Б24га ёзиб синаш» или `/b24_test`. Учебные `/test` и `/inbox_test` по-прежнему не пишут в Б24. Реальный режим отключает активную оффлайн-симуляцию/учебный инбокс, сохраняет их данные и не удаляет рабочий черновик.
2. `/deal` или `/support` открывают форму. Воронка и начальная рабочая стадия выбираются из живой Б24. Заявка поддержки в этой редакции является сделкой выбранной пользователем воронки. Воронка поддержки по названию/ID не угадывается.
3. Вводятся название, ИНН либо явный пропуск, подтверждение компании при совпадении, описание и телефон либо пропуск. Последний экран показывает воронку, стадию и ответственного. Запись происходит только после «Подтвердить». В реальном тесте имя начинается с `[ТЕСТ БОТА]`.
4. Ответственный — связанный с подтверждённой регистрацией сотрудник Б24. Для Малика: 132. Компания связывается по `RQ_INN` как в существующей форме; ИНН не является авторизацией. Ненайденная компания в формах сделки/поддержки не создаётся автоматически — это отдельная логика рабочего ОКБ.
5. `/my_crm`, «📂 Б24 ёзувларим» и `/crm_deal ID` открывают сохранённую связь с созданной записью. Текущие название, ответственный, воронка и стадия читаются из Б24.
6. «🧭 Босқични ўзгартириш» показывает стадии фактической текущей воронки с пагинацией. После выбора требуется отдельное подтверждение «✅ Б24да тасдиқлаш». «🔄 Янгилаш» перечитывает карточку.

## Сохранение связей и защиты

- Б24 получает `originatorId=datfo-sales-telegram` и уникальный `originId`; локальная операция сохраняет ID/ссылку, автора, воронку и подтверждённую форму. Создания без подтверждённого ответа ищутся чтением; неизвестный результат не вызывает повторное создание. Поиск происхождения охватывает воронки: внешний перенос записи не теряет её ID и не приводит к созданию дубля.
- Кнопки проверяют приватный чат, подтверждённую регистрацию, локальную связь, внешние маркеры и текущего ответственного. Менеджер не получает произвольные записи CRM по чужому ID. Администратор может проверить запись, созданную ботом; это не произвольное управление всей CRM.
- Выбранные стадии/намерения сохранены в основной SQLite. Перед записью сверяются фактические стадия, воронка, время обновления и ответственный; стадия перечитывается из живого справочника. Одно намерение атомарно переводится из `prepared` в `sending`. Повтор той же кнопки не повторяет запрос обновления. Сбой/отказ сохраняются; неизвестный результат проверяется чтением, старое действие не отправляется автоматически снова.
- Изменяется только `stageId`. Переход подтверждается независимым чтением. Если условия стадии/права Б24 не позволяют переход, бот показывает отказ; условия не обходятся.
- REST Б24 не предоставляет использованному `crm.item.update` атомарное условие по `updatedTime`. Проверка до записи предотвращает применение устаревших кнопок, но не гарантирует отсутствие внешнего изменения в узком промежутке между чтением и записью. Действие и последующее фактическое состояние фиксируются отдельно; автоматические переходы роботов Б24 не объявляются переходами бота.
- Обновления Б24 в Telegram видны после «Янгилаш»/повторного открытия, автоматическая подписка на изменения и настоящая доставка нескольким сотрудникам не подключены.

## Подготовленное изменение доступа — ещё не применено

В интерфейсе подтверждено: «Sales Dashboard REST-Export», ID 2955, состоит в общей роли «Dashboard profile REST» вместе с ID 922. В воронке «DATFO Новые продажи» эта роль не разрешает добавление/изменение. Общую роль менять нельзя без влияния на второго участника.

Для первой живой проверки предлагается **отдельная роль «Datfo Sales bot — подключение 2955»**, только пользователь 2955 и только воронка **43 «DATFO Новые продажи»**:

| Действие | Предлагаемый уровень |
|---|---|
| Просмотр | Все, внутри выбранной воронки |
| Добавление | Все, внутри выбранной воронки |
| Изменение | Все, внутри выбранной воронки |
| Перемещение на стадию | На любую стадию данной воронки |
| Удаление / экспорт / импорт / изменение роботов / настройка CRM | Не добавлять |
| Прочие воронки и существующие роли | Не менять |

«Все» необходимо, поскольку API-пользователь 2955 создаёт записи с ответственными менеджерами, например 132; это не его собственные карточки. Роль расширяет права подключению в выбранной воронке и требует подтверждения перед сохранением. Снимок текущих прав: `qa/sales-b24-rights-before.jpg`. Выбор и права других воронок остаются отдельным вопросом.

## Проверки

161 тест прошёл, включая 17 новых проверок настоящих форм и стадий и одну проверку подсказки реального тестового режима: подтверждение/отмена, ответственный менеджер и ИНН, выбранная техническая воронка, потеря результата создания и сообщения, отсутствие дубликатов, подтверждение стадии, старые/чужие кнопки, изменение владельца/происхождения, отказ, удаление стадии, перезапуск и внешний перенос воронки. Живая попытка со стабильным номером запроса завершилась `ACCESS_DENIED`; повтор использовал тот же запрос с предварительным поиском. Подтверждённых тестовых сделок этой проверкой не создано.
