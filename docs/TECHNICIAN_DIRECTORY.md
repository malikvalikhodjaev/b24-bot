# Назначение заявки технику из структуры компании

## Подтверждённое поведение — 8 октября 2026

После формы поддержки менеджер выбирает «📥 На распределение» либо «🛠 Назначить технику». Второй вариант доступен даже при единственном зарегистрированном пользователе бота. Контактное лицо аптеки остаётся самостоятельной сущностью и не является исполнителем ФОМ.

Источник списка — структура Б24: «Отдел технической поддержки» №17 → региональные группы №60, 61, 62, 63 и их дочерние подразделения. Подтверждены 34 активных сотрудника: R1 — 10, R2 — 8, R3 — 7, R4 — 9. Сотрудники общего родительского отдела, продажи, внешние и неактивные аккаунты в этот список не включаются. Это ограничение по подразделениям, а не догадка по должности. Совпадение ФИО не объединяет два разных аккаунта: для одинаковых имён показывается ID Б24.

В списке восемь строк на страницу, поиск по части имени или фамилии, фильтры четырёх регионов, возврат ко всем техникам и обновление справочника. Регистрация сотрудника в Telegram отмечается «Telegram ✅», если подтверждена роль техника. Числовой выбор относится к сохранённому показанному списку; изменение структуры не сдвигает номера во время выбора. Список кэшируется на пять минут; активность и принадлежность выбранного сотрудника региональному подразделению проверяются свежим чтением перед сохранением. Техника с ID автора не предлагают.

Для техники из R1 исходная очередь — R1; для R2–R3–R4 — объединённая очередь Б24. Менеджер может изменить очередь на проверке. При отправке на распределение остаются прежние стадии «Распределитель», «Новые заявки, R1», «Новые заявки, R2-R3-R4».

## Б24 и Telegram

Выбранный техник становится ответственным в Б24 по его нативному ID. Имя и региональные подразделения сохраняются в nullable `fom_requests.technician_details`; исторические записи и очереди не переписываются. Есть подключённый подтверждённый аккаунт с ролью `tech` — owner и получатель указывают на его Telegram ID. Нет такого аккаунта — status=assigned, owner=NULL, initial_recipient=0; Telegram ID из ID Б24 не придумывается, уведомления другим людям не отправляются. Такая заявка не является общей очередью и недоступна для захвата чужому технику.

Позже сотрудник проходит регистрацию, администратор подтверждает её и роль `tech`. По совпадающему ID Б24 бот читает актуальную связанную CRM-карточку, привязывает Telegram owner и один раз уведомляет техника. Само подключение не изменяет сделку Б24. Незарегистрированному исполнителю доступны обычные действия Б24; бот принимает движение в работу/завершение, сохраняет назначенного сотрудника и времена. Для ещё не подключённого техника автор заявки или администратор могут вернуть заявку на распределение. После этого именованное назначение очищается.

Поиск контакта и создание новой аптеки остались прежними, см. [SUPPORT_CONTACT_ROUTING.md](SUPPORT_CONTACT_ROUTING.md). Потерянный ответ на создание заявки проверяется чтением по стабильному origin, повторный add не выполняется. Отзыв доступа автора блокирует новое создание. Если автоматизация Б24 меняет явно выбранного исполнителя, бот не подтверждает назначение как успешное и не перезаписывает изменение молча. Сообщение об успешном назначении показывается только после подтверждения Б24.

## Интерпретации и открытые вопросы

Выбор сотрудников четырёх региональных групп соответствует запросу «техники из структуры компании»; руководители и общий служебный аккаунт родительского отдела не включены в выбор исполнителя. Для изменения состава используется Б24, после чего обновляется справочник. Привязка бизнес-региона аптеки к R1–R4 не устанавливалась наугад; очередь выбирается отдельно или подставляется по группе конкретного техника. Отбор всех уведомляемых/видящих общую очередь сотрудников строго по региону не менялся.

Ожидается ручная проверка реального назначения на выбранного техника с действующими роботами Б24 и регистрация реального исполнителя в Telegram. Интеграция с office.aifom.uz по-прежнему отложена. Бот остаётся локальным процессом; Git-выпуска этой редакции нет.
